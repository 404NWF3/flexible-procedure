## 预先固定的设计

分析原始 FIFO、同类优先、上一轮冻结的 `c20_hybrid` 三个策略。每个策略使用 1 个标准情景和 16 个单参数扰动情景：4 个参数 × −5%、−2%、+2%、+5%。每格 200 次，共 51 格 / 10,200 次，禁止看完结果再换扰动范围、追加样本或筛选策略。

| 参数 | 标准值 | 扰动的实现 |
|---|---|---|
| 物件到达速率 | 名义 1.25 件/min；批间隔均值 10 min | 批间隔均值除以 `1+δ`，批量仍为均匀 5–20，产品比例不变 |
| 加工速度 | 现有所有产品/工序均值对应的速度，倍率 1 | 实际加工时长除以 `1+δ`；均值和标准差同缩放，CV 仍为 0.10 |
| 平均无故障工作时间 MTBF | 6,000 有效工作分钟 | 指数寿命均值乘以 `1+δ`，只累计加工与换模时间 |
| 平均修复时间 MTTR | 240 min | 指数维修时长均值乘以 `1+δ` |

这里的加工速度是所有工序同比例变化，不是单独改变某个工位。速度增加 5% 对应时长变成原来的 `1/1.05`，不是 0.95。没有改变机床数量、缓冲、路线、批量分布、产品比例、换模时间、价格、费率、观察窗口或会计规则。

策略用于排序的**名义加工时间仍为标准值**；真实物理加工过程发生偏差，策略仍可响应队列、模具状态和等待时间。这是固定控制器面对参数偏差的灵敏度，不包含“知道新参数后重新校准调度”的效果。

## 样本、核算与统计

200 个新种子在正式运行前生成并提交 SHA-256 承诺。每个种子用于全部 17 个情景、全部 3 个策略；分析按重复编号配对。到达批次和产品抽样共享随机流，改变速率会改变实际到达时间与窗口内批次数，不能强行保持到达数量不变。加工随机量按工件/工序绑定；寿命与维修按机床的相应随机流绑定。

标准参数结果也用本轮新种子重新计算，不借用上一轮开发/验证/确认的均值。预检使用公开种子 43，全部排除在这 200 个正式样本之外。

经营贡献仍是 `[0,2400)` 工作分钟内的完工收入减加工费、换模费；未完成工件的费用照计，不计算存货残值。加工与换模按每台机床 100 元/h 计费，维修、阻塞、空闲不计费。不包含材料、人工、改变参数的实施成本等，不能当作净利润或投资建议。

主要指标为经营贡献。48 个非零参数对比（3 策略 × 4 参数 × 4 幅度）统一使用双侧配对 t 区间，Bonferroni 分配 `0.05/48`，整体 α=0.05；t 方法依赖正态/大样本近似。次要指标包括成品、分产品交付、线外积压、在制、故障、维修/阻塞、已完成件周期，区间均为描述性 95%，不作同样的家族错误率承诺。

每个配对变化为 `Y(扰动, i) − Y(同策略标准, i)`。相对变化使用均值之比，不是逐次百分比的均值；近似区间用包含基准均值不确定性的配对 Delta 法。基准均值为零时不报告百分比。

局部弹性为 `[平均G(+5%) − 平均G(−5%)] / [0.10 × 平均G(标准)]`，近似描述性 95% 区间也保留三组样本的配对依赖。它是这一邻域的中央差分，不是全局定律或无条件改善空间。正负扰动可不对称；区间跨零表示当前精度下方向未确定，不能当作没有影响。

没有研究参数交互、工位分别变速、长期稳态、保供约束或需求上限。本轮的 α 族针对参数问题，未修改或重置上一轮优化研究的 α 账本。

## 实现与隔离

新增 `SensitivitySimulation` 复用原有机床、随机流、队列、计量和可信策略适配器。只在环境启动前包装实际加工时间回调；其余参数通过独立 `SimulationConfig` 实例设置，没有修改原模块的全局路线或任何旧文件。

三个策略均校验冻结 SHA-256，使用原始源代码。为降低固定策略的大批量复核开销，在进程内执行并保持相同 JSON 输入/输出语义与动作哈希；这不是可运行任意候选代码的安全沙箱。7 项预检覆盖倒数转换、共同到达流、名义观察不变、手算加工/成本和非法输入；3 策略 ×（标准 + 4 类 +5% 情景）共 15 组完整轨迹及动作摘要与原隔离执行器逐字段一致。两个原生对照的标准轨迹也与原模拟器一致。

受控调度由冻结策略源决定；基础配置中的 `policy_name` 是保留的兼容字段，判断本轮实际策略应使用记录中的 `policy` 和协议中的 `policy_sources`，不能仅看该兼容字段。

`protocol.json` 的 `source_commit` 记录注册时的仓库基线；新增执行文件由 `frozen_files` 中的 SHA-256 单独冻结。`prior_archive_files` 锁定上一轮源代码、策略、网页、记录和依赖锁；每格运行前及完成时复核。页面渲染、图形导出和审计属于结果呈现，不会影响已冻结的模拟或统计。

## 使用与复核

已有结果直接打开 [静态页](../../docs/sensitivity/index.html)。生成物已提交，不需安装依赖即可查看。需要核验时，在仓库根目录执行：

```bash
uv venv .venv-research --python 3.12
uv pip install --python .venv-research/bin/python -r research/requirements.txt
.venv-research/bin/python research/sensitivity/audit_snapshot.py
.venv-research/bin/python research/sensitivity/render.py --check
```

公开审计重新核算全部统计、独立用方差/协方差核对 48 个主要配对区间，检查 10,200 条记录、51 格样本覆盖、CSV、日志链、物理情景、冻结摘要及旧归档完整性。只读取统计，不运行仿真。

保有本地原始证据时，运行 `audit_snapshot.py --full`：额外验证全部原始轨迹哈希、种子承诺，并逐格检查第一和最后一次轨迹的种子、参数和贡献，共 102 份内容抽查。输出会分别列出全量哈希与内容抽查数量，不把抽查称为全量重算。

静态页可用 `render.py` 重建。科研图由 `figures.py` 从同一份最终统计导出 SVG/PNG/PDF；额外依赖见 `requirements-figures.txt`，中文图需要 Noto Sans CJK 字体。图表没有从浏览器截图取值。

历史执行顺序为：`preflight.py` → `runner.py init` → `runner.py run --workers 4`。现有研究禁止重复初始化或自动重跑。故障时保留全部记录，先审查原因；不要删除协议、记录或种子重新开始以取得更好结果。
