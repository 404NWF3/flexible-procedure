## 当前项目的运行约定

- 本项目使用 uv 管理 CLI。请在 `soft-procedure` 项目根目录执行命令；本技能及依赖它的技能中，所有 `sufe ...` 命令均使用 `uv run sufe ...` 执行。
- 本项目的四个 SUFE Skills 安装在项目内 `.agents/skills/`。上游 `sufe doctor` 只检查用户全局技能目录；若只报告 `~/.agents/skills` 或 `~/.claude/skills` 缺少 SUFE Skills，另行确认项目内四个 `SKILL.md` 存在后即可视为技能安装正常，不需要重复全局安装。
- 上述差异仅适用于技能目录检查。浏览器或认证状态缺失、失效时，仍按下述流程处理。

## 核心概念

- **浏览器环境**：`sufe` 依赖本地浏览器完成自动化操作，首次使用前需确保环境就绪。
- **认证状态**：`sufe` 在本地保存登录凭据，业务调用前自动验证；过期或缺失时需执行 `sufe auth`。

## 指令速查表

| 指令 | 说明 |
|---|---|
| `sufe doctor` | **环境检查**：检查浏览器环境是否就绪、认证配置是否存在，以及登录状态是否可用 |
| `sufe install` | **环境安装**：安装所需的浏览器环境与 Agent Skills |
| `sufe auth` | **用户认证**：执行登录，并将认证状态保存到本地 |
| `sufe me` | **查看当前用户**：显示当前已登录用户的学号、姓名和学院信息 |

> **⚠️ 重要约束**  
> `sufe install` 涉及浏览器下载与本地文件系统写入，属于用户交互敏感操作
> `sufe auth` 可能涉及浏览器弹出或凭据输入，同样属于用户交互敏感操作。
> 无论何种场景，Agent **必须** 明确提示用户自行运行对应命令，不得自动触发。

## 工作流

### 业务前置检查

当被其他技能触发检查时，应确保环境就绪。

1. 执行 `sufe doctor`
   - 浏览器缺失: 提示用户执行 `sufe install`
   - 认证配置缺失/认证状态缺失/失效: 终止业务命令，明确提示用户执行 `sufe auth`
2. 全部正常: 直接执行业务命令

### 直接触发

当用户主动询问环境、登录、认证或身份相关问题时：

- 优先执行 `sufe doctor` 获取当前环境状态，根据输出向用户汇报：
   - 浏览器缺失 → 告知需 `sufe install`
   - 认证配置缺失/认证状态缺失/过期 → 告知需 `sufe auth`（明确提示用户自行执行）
   - 全部正常 → 告知已就绪
- 若用户想确认身份信息 → 执行 `sufe me`
- 若用户表示已完成 `sufe auth` → 可执行 `sufe doctor` 或 `sufe me` 验证
