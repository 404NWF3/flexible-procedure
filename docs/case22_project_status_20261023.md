## 当前项目状态

### 已有实现/结果

- SimPy 项目包含单件路线、机器状态、换模/故障续作、下游阻塞、配对实验及 CSV/JSON/HTML 输出。
- SimPy 已扩展新版任务书的核心四方案：FIFO/同类优先 × M4 1/2 台；新增机床购置价 500,000 元作为资本投资单列。
- 当前结果按窗口内实际完工产品计销售收入；运行费默认按加工与换模时间 × 100 元/小时，也可切换为机床全时或整线全时口径。`operating_contribution` 为收入减已知运行费，不等同净利润。
- 核心结果包含10次重复、种子42–51；通过结果校验脚本的结构、方案、种子、数量守恒、状态占比和收入-成本-贡献勾稽检查。
- 此前 c20 的 140,782.90 元只保留为另一分支/历史仿真线索，不能当作当前仓库模型的已复核结果；它还有 P1/P2 低产的公平性风险。
- 新增机器状态截图显示 M2 利用率99.3%、M1阻塞86–89%、M3两台负荷明显不均；总机器工序数1095不等于成品数，M5合计350可能是总成品数，须以Sink计数核对。

### 尚未完成或待确认

1. **经济口径：**100 元/小时是否含折旧；2400分钟是否等于一个实际生产周；每年生产周数；设备残值；新增机床是否专用于本产线。
2. **回收期：**`investment.payback_periods` 是新增购置投资除以配对经营贡献增量均值，单位为仿真观察期；区间跨0时状态为方向不确定。确认时间映射与现金流假设前，不应将它写成现实回收周数。
3. **Simio：**ZIP 原型与新版 DOCX 目标结构不同；新版 DOCX 是设计规格，不是模型运行证明。ZIP 的预记计划工时问题尚未在 Simio 中修正并通过截点测试。
4. **V&V：**Arena S01–S08 的方案已有文档，但仓库没有完整逐项实测证据；Simio 共享输入的确定性测试和跨模型成本对账仍待执行。
5. **Arena 许可：**此前收到临时学术许可激活信息，但当前许可是否实际启用、实体上限是否解除、能否完成长时多重复实验，需在软件中实测确认。不要依据旧 Student 限额推断当前许可。
6. **优化结论：**c20 尚未在当前模型、成本定义和公平性/交期约束下重跑；不要宣称全局最优。
7. **截图证据：**三张机器状态截图已归档，但场景、种子、运行时长和重复编号缺失；分产品完工构成及 M3派工均衡性需要原始结果核对。
8. **原始附件：**审阅报告已同步内容分析，原始 Simio ZIP 和部分附件未直接进入公开仓库；如需上传源文件，应先筛除不宜公开的二进制、授权内容、个人信息与过时规格。

## 推荐执行顺序

1. 由任务书/教师确认经济定义：100元/小时的组成、2400分钟对应的现实周期、每年生产周数、10年与残值假设、设备分摊范围。
2. 保留“折旧前简化经营贡献”作为当前任务定义结果；确认后再新增“折旧后期间收益”，并明确该列不替代现金回收期。
3. 针对新增一台专用设备，按明确口径展示 961.54 元/周（52周/年）或 1,000 元/生产周（50周/年）的折旧示例；不得把50万元一次性扣在单个仿真周期。
4. 先运行确定性成本校准：固定一件 P1、关掉故障和换模，核对截止时刻实际已耗用工时、产值与费用；再做四路线、换模、故障、阻塞、守恒 V&V。
5. 补齐本次截图的运行元数据与 P1–P4 Sink 完工数，先排查 M3派工不均及 M1阻塞来源。
6. 用同一模型版本、相同随机输入和明确成本拆分，运行核心四方案；验证原始结果与汇总、置信区间、分产品产量及回收期列。
7. 通过模型门禁后，才重新评估 c20 和公平性/交期约束方案。
